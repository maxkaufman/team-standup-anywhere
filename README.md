# Team Standup Anywhere

A full-stack async standup platform for remote teams. Team members submit daily standups — what they did yesterday, what they're doing today, and any blockers — along with a mood check-in. Managers get a live dashboard with mood trends, completion rates, and team analytics.

**Stack:** React · TypeScript · Java 21 · Spring Boot · GraphQL · PostgreSQL · AWS (ECS, RDS, Lambda, CloudFront, S3)

---

## Features

- **Daily standup submission** — structured yesterday/today/blockers form with a 1–5 mood rating
- **Team dashboard** — real-time stats including average mood, today's completion rate, and active blockers
- **30-day mood trend chart** — visualizes team sentiment over time
- **Team management** — create a team or join one via invite code; role-based access (Member / Lead)
- **Standup history** — paginated personal standup log
- **Avatar uploads** — direct browser-to-S3 via presigned URLs, no proxying through the backend
- **Scheduled email reminders** — AWS Lambda queries the DB each weekday morning and sends SES reminders to members who haven't submitted yet
- **JWT authentication** — access + refresh token pair, stateless backend

## Architecture

```
Browser
  │
  └── CloudFront CDN
        ├── /graphql  ──→  ALB  ──→  ECS Fargate (2 tasks)
        │                                  │
        │                              Spring Boot
        │                            (GraphQL API)
        │                                  │
        │                           RDS PostgreSQL
        │                             (Multi-AZ)
        │
        └── /*  ──→  S3 (React SPA)

Lambda (Python) ──→ EventBridge cron (weekdays 9am EST)
    │                    │
    └── RDS (query)      └── SES (send reminders)

S3 Avatars bucket  ←──  presigned PUT from browser
```

**Infrastructure is fully defined in Terraform** (`infra/main.tf`) — VPC with public/private subnets, NAT gateway, ALB, ECS cluster, RDS instance, CloudFront distribution, Lambda function, EventBridge rule, Secrets Manager, and all IAM roles.

## Local Development

**Prerequisites:** Docker, Node 20+, Java 21, Maven 3.9+

### Option A — Docker (recommended)

```bash
docker-compose up -d
```

This starts PostgreSQL, the Spring Boot backend (port 8080), and the Vite dev server (port 5173) with hot reload. The backend auto-runs Flyway migrations on startup.

### Option B — Run services individually

**Database**
```bash
docker-compose up -d postgres
```

**Backend** (uses H2 in-memory DB by default — no Postgres needed)
```bash
cd backend
mvn spring-boot:run
# GraphQL API: http://localhost:8080/graphql
# GraphiQL explorer: http://localhost:8080/graphiql
```

**Frontend**
```bash
cd frontend
npm install
npm run dev
# App: http://localhost:5173
```

## GraphQL API

The entire API is a single GraphQL endpoint at `/graphql`. Key operations:

```graphql
# Auth
mutation Login($email: String!, $password: String!)
mutation SignUp($input: SignUpInput!)
mutation RefreshToken($token: String!)

# Standups
mutation SubmitStandup($input: StandupInput!)
query TodayStandup
query MyStandups($limit: Int, $offset: Int)

# Team & analytics
query DashboardData($teamId: ID!, $date: String!)
mutation CreateTeam($name: String!)
mutation JoinTeam($inviteCode: String!)

# Profile
mutation UpdateProfile($input: ProfileInput!)
mutation GenerateAvatarUploadUrl($fileName: String!, $contentType: String!)
```

## Database Schema

```sql
users      id, email, password (bcrypt), name, avatar_url, role, team_id, created_at
teams      id, name, invite_code (unique), created_by, created_at
standups   id, author_id, team_id, yesterday, today, blockers, mood (1-5), created_at
```

Indexes on `standups(team_id, created_at)` for fast dashboard queries.

## AWS Infrastructure

Provisioned entirely with Terraform:

- **VPC** — two AZs, public/private subnets, single NAT gateway
- **ECS Fargate** — 2 task replicas behind an Application Load Balancer; secrets injected from Secrets Manager at runtime
- **RDS PostgreSQL 16** — Multi-AZ, encrypted at rest, 7-day automated backups
- **CloudFront** — serves the React SPA from S3; proxies `/graphql` to the ALB with `Authorization` header forwarding
- **Lambda** — Python 3.12, runs inside the VPC, queries RDS and fires SES emails; triggered by EventBridge on `cron(0 14 ? * MON-FRI *)` (9am EST)
- **S3** — separate buckets for frontend assets and user avatars (CORS-enabled for presigned PUT)
- **Secrets Manager** — DB password and JWT secret injected as environment variables into ECS tasks
- **CloudWatch Logs** — ECS task logs retained for 30 days

## Configuration

| Variable | Description |
|---|---|
| `JWT_SECRET` | HS256 signing key (min 256-bit) |
| `DB_HOST` / `DB_NAME` / `DB_USERNAME` / `DB_PASSWORD` | PostgreSQL connection |
| `AWS_REGION` | S3 presigned URL region |
| `SENDER_EMAIL` | SES verified sender address |

In production these are all provided via ECS secrets (Secrets Manager) or environment variables. Locally the backend defaults to H2 and uses the dev values in `application.yml`.
